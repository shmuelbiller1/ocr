# Optional Hebrew spelling — experimental

This is a separate **AGPL-3.0-only plugin distribution**, not a new built-in
plugin and not a replacement for raw OCR. Project-authored source retains MIT
notices; the dictionary is **not MIT**. Hunspell has its own LGPL/GPL/MPL terms.
Read NOTICE.txt, LICENCES and the included SOURCE archives. Do not assume that
using a subprocess exempts a combined distribution from copyleft obligations.
No legal compliance certification or change to the core project's license is
claimed. No OCR weights (including NC assets) are included in this package.

## A major quality limitation

The dictionary is Hspell **1.4**, generated by LibreOffice from that project's
linguistic data. Upstream WHATSNEW explicitly says it follows the spelling
standard **before June 2017**, not the later standard. Modern accepted spellings,
names, Aramaic/Yiddish and school terminology can be flagged. This is a small
candidate to evaluate, **not a proven best or complete modern Hebrew checker**.
Suggestions always require individual acceptance. No language/grammar rewriting
or Google service is used. Source scans and raw OCR are never modified.

## Install on Windows without Python

Use the **built Windows plugin ZIP**, not this source-only directory:
Settings → Plugins and engines → Install ZIP, then select `hunspell-hebrew` as
the active spelling plugin. Enable it if necessary. It carries a source-built
native worker and both .dic/.aff files. No browser, Python installation, online
activation, runtime package download or model host is needed. The source-only
folder intentionally reports unavailable until built. The plugin is not yet
included in the existing v0.4.0 downloads; its published availability must not
be inferred from this README.

“Keep this word” saves to the app's per-user `spelling/hunspell-hebrew-personal.txt`.
It never appends words to the licensed upstream .dic. Personal vocabulary stays
outside the installed plugin and survives its removal/reinstallation. The
legacy spelling module uses a **different custom plain-list format**, not real
Hunspell affix flags. Select this plugin before choosing a Hunspell .dic file;
it requires a matching UTF-8 .aff. Custom dictionaries remain the user's trust
and licensing responsibility.

Mixed Latin/Hebrew tokens, digits, internal-quote abbreviations and words under
three letters are conservatively skipped. Niqqud is removed for lookup only;
proposals retain the original text and Unicode offsets. At most three native
suggestions are shown. Unknown words with no candidate are flagged without a
fabricated replacement. Detection/ranking is word-based, not contextual.

Checking uses a local killable subprocess, 8-second timeout and a 2,048-distinct-
word limit per check. Exceeding a limit fails with an actionable error, not partial
silent checking. Suggestions run synchronously in the existing suggestions UI;
the timeout bounds a slow request but this is not a background grammar service.
Uninstall this user plugin in Settings to remove its runtime/dictionary files.
No built-in engine or raw recognition setting is changed.

## Reproduce (developer only)

```
python -m pip install cmake==3.31.6
python tools/build_spelling_plugin.py --output build/hebrew-spelling
python tools/verify_spelling_plugin.py --zip build/hebrew-spelling/hunspell-hebrew-win64.zip --report build/spelling-report.json
```

Requires a local C++ compiler (MSVC on Windows). The builder downloads only
pinned, hash-checked **source/data**, compiles Hunspell/our worker locally and
includes licenses, Hspell generators, Hunspell source, application sources and
build recipe. Input pins and original URLs are in upstream-pins.json. The
uncompressed dictionary pair is about 7.9 MB; the final package size must be
measured, not inferred from the Firefox add-on size.


For rebuilding the included corresponding source without a Git checkout, unpack
`SOURCE/workbench-source.zip`, then run its `tools/build_spelling_plugin.py` as
above. Its captured file manifest allows repackaging without `.git` and does
not scrape untracked/private files. To avoid re-downloading already supplied
inputs, place the two SOURCE tarballs and the three files under `data/` into
`build/hebrew-spelling/downloads/` (the dictionary README is named
`README_he_IL.txt`). The builder validates the same pinned hashes from cache.
Upstream Hspell's generators and `make hunspell` recipe are in its source tarball;
LibreOffice's UTF-8 output is preserved verbatim alongside its notice. Build
dependencies still need a developer-provisioned compiler/CMake. None of this is
required by an ordinary app user.
